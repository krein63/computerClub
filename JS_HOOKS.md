# Подготовленная структура для JavaScript

Этот файл описывает контракт следующего этапа. Перечисленное поведение ещё не реализовано: в midterm есть только HTML/CSS. ID должны сохраняться после тега `midterm`.

## Общие элементы

`main-navigation-toggle` управляет CSS-меню. `main-navigation` содержит все ссылки; `nav-index`, `nav-prices`, `nav-computers`, `nav-booking`, `nav-games`, `nav-rules`, `nav-about` — пункты меню. `site-header`, `site-footer`, `main-content` — общие области. Ссылка пропуска навигации переводит фокус в основное содержимое.

Ссылки карточек содержат настоящие якоря. Они не передают выбранное значение между страницами: пользователь выбирает его в форме. Позже JavaScript может прочитать hash и переключить существующую радиокнопку, не добавляя HTML вручную.

## План визита

Форма `booking-form`. Основное действие `booking-create-button`; сброс `booking-reset-button`.

| Ввод | Ограничения HTML | Готовый вывод |
|---|---|---|
| `customer-name` | Обязательно, 2–40 символов, nickname | `booking-name-output` |
| `booking-date` | Обязательно, date | `booking-date-output` |
| `booking-time` | Обязательно, time, местное время Астаны | `booking-time-output` |
| `player-count` | Целое число от 1 до 45 | `booking-players-output` |
| `booking-tariff` | Один из hourly, three-hours, night, private | `booking-tariff-output` |
| `booking-duration` | 1, 2, 3 или 5 часов как планируемая длительность | `booking-duration-output` |
| `zone-main`, `zone-duo`, `zone-private` | Одна required radio-группа gaming-zone | `booking-zone-output` |
| `booking-comment` | Необязательно, до 300 символов | `booking-comment-output` |
| `booking-agreement` | Ознакомление с правилами обязательно | Отдельный вывод не нужен |

`booking-summary` — видимая карточка; `booking-summary-empty` — её начальное пояснение. `booking-result` — пустая область динамического сообщения. `booking-error` и `booking-success` подготовлены для ошибки и подтверждения создания **личного плана**, а не реальной брони. У каждого поля есть пустой контейнер ошибки, связанный через `aria-describedby`; у радиогруппы он общий — `gaming-zone-error`.

`booking-total-output` — место для ценового ориентира. `booking-total-help` объясняет, что точная сумма не рассчитывается по неподтверждённым ставкам. Начальное тире обозначает отсутствие выбранного значения, а не бесплатный визит.

При подключении поведения:

1. Проверять поля через Constraint Validation API, затем дату/время и согласованность тарифа с пожеланиями. Не разрешать прошедшее время; учитывать Астану. Нельзя навечно фиксировать сегодняшний `min` в HTML.
2. Для трёхчасового тарифа согласовать длительность с 3 часами; Private связан с зоной Private. Ночь — выбранный пакет, но его точные часы в источнике не заданы. Не вычислять и не обещать эти условия самостоятельно.
3. Присваивать классы ошибок существующим полям, заполнять связанные сообщения, переводить фокус к первой ошибке.
4. Заполнить существующие output-элементы текстом, скрыть начальное пояснение, показать сообщение о созданном локальном плане. Не сообщать о резервировании, отправке, оплате или подтверждении сотрудником.
5. Показывать цену «от» по выбранному опубликованному варианту либо понятное состояние «точная стоимость не определена». Не умножать Private 2 500 ₸ как часовую ставку и не выдавать нижнюю границу за окончательный счёт.
6. Сбросить и поля, и выходные значения, и классы ошибок, и сообщение результата при очистке. В midterm нативный reset сбрасывает только поля, поскольку динамических данных ещё нет.

## План игры

`game-plan-form` содержит `game-plan-name` (2–80 символов), `game-plan-goal` (required select) и `game-plan-notes` (до 300 символов). `game-name-options` — подсказки названий. Пользователь может ввести другое название как личное пожелание; это не утверждение о наличии игры.

`save-game-plan` — подготовленная кнопка; `reset-game-plan` — сброс. `game-plan-submit-guard` — скрытая отключённая submit-кнопка, которая блокирует нативную отправку по Enter до подключения обработчика.

Готовые области:

- `game-plan-error`, `game-plan-success` — пустые сообщения с live region.
- `game-plan-result` — постоянно видимая оболочка результата.
- `game-plan-empty` — текст пустого состояния.
- `game-plan-details` — скрытый список параметров.
- `game-plan-result-name`, `game-plan-result-goal`, `game-plan-result-notes` — пустые значения для одного плана.

Будущий обработчик валидирует ввод, заполняет значения через `textContent`, заменяет пустое состояние результатом, показывает успех. Для пустой заметки допустим текст «Без заметки». Очистка возвращает начальное состояние. Нет серверного запроса установки, чужого подтверждения или нескольких участников процесса.

## Карточки и цены

`home-main-card`, `home-duo-card`, `home-private-card` и карточки зон на странице компьютеров имеют собственные ID. `tariff-*-price` и `comparison-*-price` адресуют одинаковые ценовые значения на странице тарифов. `counter-strike-card`, `dota-card` — карточки игр; `game-cards` — их контейнер. Для будущего обновления существующего содержания не требуется менять структуру вручную.

## CSS состояния

| Класс | Назначение |
|---|---|
| `is-hidden` | Полностью скрывает элемент, включая его участие в раскладке |
| `is-active` | Выделяет текущий вариант цветом и насыщенностью |
| `is-selected` | Обозначает выбранную карточку рамкой |
| `is-error` | Цвет и фон ошибки, рамка поля |
| `is-success` | Цвет и фон успешного результата |
| `field-error` | Размер, цвет и отступ пояснения ошибки |
| `state-message` | Рамка, внутренний отступ и скругление сообщения |

Bootstrap также предоставляет `active`, `disabled`, `is-invalid`, `is-valid`, `alert-*` и стандартные focus-состояния. Нужные состояния уже входят в локальный CSS. При динамической ошибке следует синхронизировать `aria-invalid`, содержимое ошибок и фокус; при успехе очистить прежние ошибки.
